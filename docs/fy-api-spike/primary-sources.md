## API-key-accessible quota endpoints

Upstream references below use New API tag [`v1.0.0-rc.37`](https://github.com/QuantumNous/new-api/tree/v1.0.0-rc.37), matching the target's reported version; matching a version string does not verify target implementation. One API references use commit [`8df4a2670b98266bd287c698243fff327d9748cf`](https://github.com/songquanpeng/one-api/tree/8df4a2670b98266bd287c698243fff327d9748cf).

| Software | Endpoint | Source-backed meaning |
| --- | --- | --- |
| New API | `GET /api/usage/token/`, bearer API key | Preferred token-specific candidate. Returns raw stored quota: `total_granted = RemainQuota + UsedQuota`, `total_used`, `total_available = RemainQuota`, plus `unlimited_quota`, model allowlist fields and `expires_at` (`-1` becomes `0`). The response envelope uses `code: true`, not `success: true`. [Handler](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/controller/token.go#L229-L275), [official endpoint doc](https://docs.newapi.pro/zh/docs/api/management/token-management/usage-token-get). |
| New API and One API | `GET /v1/dashboard/billing/subscription` and `GET /v1/dashboard/billing/usage`; aliases without `/v1` | Both use API-key `TokenAuth`. Subscription limits are **remaining plus used**, not remaining alone; usage is used quota multiplied by 100 after display conversion. Scope is token or user depending on `DisplayTokenStatEnabled`. Unlimited tokens produce a subscription sentinel of `100000000`, not a measured balance. [New API routes](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/router/dashboard.go), [handler](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/controller/billing.go); [One API routes](https://github.com/songquanpeng/one-api/blob/8df4a2670b98266bd287c698243fff327d9748cf/router/dashboard.go), [handler](https://github.com/songquanpeng/one-api/blob/8df4a2670b98266bd287c698243fff327d9748cf/controller/billing.go). |

New API's token-usage route uses `TokenAuthReadOnly`: it permits expired/exhausted tokens but rejects missing/unknown keys, explicitly disabled tokens and disabled users. Billing instead uses normal relay authentication; One API token validation rejects expired/depleted tokens. Thus an exhausted key's billing failure is not a balance reading. Account self/token-management routes use `UserAuth`, a distinct session/access-token mechanism; do not assume an inference key authorizes them. [New API routing](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/router/api-router.go), [auth](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/middleware/auth.go); [One API routing](https://github.com/songquanpeng/one-api/blob/8df4a2670b98266bd287c698243fff327d9748cf/router/api.go), [auth](https://github.com/songquanpeng/one-api/blob/8df4a2670b98266bd287c698243fff327d9748cf/middleware/auth.go), [validation](https://github.com/songquanpeng/one-api/blob/8df4a2670b98266bd287c698243fff327d9748cf/model/token.go).

Raw quota is accounting credit, not a model token count. New API billing divides by `QuotaPerUnit` in USD mode; CNY mode also multiplies by the exchange rate, while token-display mode leaves raw quota unchanged. The legacy `*_usd` names alone therefore do not guarantee USD units. Use the explicit unlimited flag and public display settings; do not present the sentinel as money. [New API billing conversion](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/controller/billing.go).

## Rate-limit semantics, not target entitlements

- **New API API/control-plane limits:** global API and critical limiters are client-IP keyed when enabled. Token usage inherits both; legacy billing inherits the global API limiter. Redis uses an atomic fixed window; memory uses a rolling timestamp queue. Rejection is HTTP 429 with `Retry-After` when positive (Redis remaining TTL; memory full configured duration). Redis check failure is 500. [Routes](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/router/api-router.go), [billing routes](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/router/dashboard.go), [limiter](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/middleware/rate-limit.go), [memory implementation](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/common/rate-limit.go).
- **New API relay request limits:** `/v1` relay routes apply `ModelRequestRateLimit` after token auth. Despite its name, counters are keyed by **user ID**, not model or API key; token/user group can override configured counts. Redis total requests use a replenishing token bucket, including failed requests; a separate rolling list records responses below HTTP 400. Rejection is 429 and this middleware does not set `Retry-After`. The memory path's supposed success-limit check actually records into a separate `_check` queue before the response, so Redis success-only semantics must not be assumed there. [Relay routes](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/router/relay-router.go), [implementation](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/middleware/model-rate-limit.go).
- **Defaults are not deployment policy:** upstream model-request limiting defaults to disabled; its configured defaults are a one-minute interval, total count `0` and success count `1000`. None establishes this gateway's configured limits, and an unlimited quota flag does not disable request pacing. [Settings](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/setting/rate_limit.go), [relay limiter](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.37/middleware/model-rate-limit.go).
- **One API:** its global API limiter uses client-IP timestamp queues in Redis/memory; configured count zero or debug mode bypasses it. It returns 429 on rejection and 500 on Redis failure; this source does not set `Retry-After`. These are One API upstream semantics, not evidence about this New API-identifying host. [Source](https://github.com/songquanpeng/one-api/blob/8df4a2670b98266bd287c698243fff327d9748cf/middleware/rate-limit.go).
